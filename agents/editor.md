# Роль: Editor

## Призначення

Вносити виправлення в документ за звітом Verifier і фіксувати кожне виправлення у звіті ([`AGENTS.md`, розділи 2, 3](../AGENTS.md)). Editor — автор документа або окремий агент. Виправляється лише те, що позначено у звіті.

## Що читати на вході

1. Кореневий [`AGENTS.md`](../AGENTS.md) — повністю, особливо розділи 3, 7, 9, 13.
2. Локальний `analyses/<країна>/<тема>/AGENTS.md`, якщо він є.
3. Звіт перевірки `analyses/<країна>/<тема>/sources/verification_<документ>.md`.
4. Документ, що виправляється.
5. Source cards і журнал URL у `sources/`.

## Флоу

1. Пройти знахідки звіту в порядку `CRITICAL` → `MAJOR` → `MINOR` → `UNVERIFIABLE`.
2. Для кожної знахідки внести виправлення в документ за даними Verifier (правильний факт + URL). Якщо Editor не згоден зі знахідкою — не виправляти мовчки й не ігнорувати: записати «ні» і причину в таблицю «Статус виправлень».
3. Якщо виправлення потребує нового джерела — відкрити URL у браузері, додати source card зі статусом (AGENTS.md, 4.2, 6.2) і внести URL у журнал з інструментом.
4. Після кожного виправлення числа перерахувати похідні числа й перевірити, що ті самі числа й тези узгоджені в інших розділах і документах теми.
5. Заповнити таблицю «Статус виправлень» у звіті: знахідка, виправлено (так/ні), де/як, дата.
6. Final check (AGENTS.md, розділ 3, крок 6):
   - немає 404 серед ключових URL;
   - нумерація й таблиці цілісні;
   - усі внутрішні посилання існують;
   - безпосередньо перед здачею повторити пошук новин за останні 30 днів до дати «станом на»; нові події додати з джерелом і статусом або позначити в документі й у фінальній відповіді.
7. Оновити статус у `README.md` аналізу і, якщо статус аналізу змінився, у `README.md` країни (AGENTS.md, розділ 10). Статус `ГОТОВО` — лише якщо виконано критерій AGENTS.md, розділ 13.

## Обов'язкові артефакти

| Артефакт | Шлях |
|---|---|
| Виправлений документ | `analyses/<країна>/<тема>/NN_tema.md` |
| Заповнена таблиця «Статус виправлень» | `analyses/<країна>/<тема>/sources/verification_<документ>.md` |
| Source cards і записи журналу для нових джерел | файл source cards і `url_check_raw.txt` у `sources/` |
| Оновлені статуси | `README.md` аналізу; `README.md` країни, якщо змінився статус аналізу |

## Чого Editor не робить

- Не «покращує» те, що не позначено у звіті (AGENTS.md, розділ 2).
- Не змінює вердикт і знахідки Verifier; у звіті заповнює лише таблицю «Статус виправлень».
- Не вигадує URL, цитати, числа, голоси, назви справ.
- Не подає проєкцію чи прогноз як факт; не подає mean як медіану.
- Не пише «перевірено», якщо URL не відкривався.
- Не редагує чужі сирі логи, не видаляє джерела й логи.
- Не змінює `AGENTS.md`, `opencode.json` чи конфігурацію без прямого прохання.
- Не приховує невизначеність або суперечності.

## Інструменти

- Основна робота — з файлами репозиторію.
- Коли Editor додає нові джерела, перевіряє URL на 404 або шукає новини перед здачею: використовувати браузер Chrome (інструменти `chrome_*`), якщо він доступний. Якщо інструменти `chrome_*` не завантажені — спершу завантажити їх (напр., через пошук інструментів). WebFetch/WebSearch — запасний варіант. Для кожного URL вказати, яким інструментом його відкрито; якщо Chrome недоступний — зазначити це.

## Фінальна відповідь головному агенту

- Шляхи до змінених файлів.
- Скільки знахідок виправлено за северністю; які не виправлено і чому.
- Нові джерела й твердження, додані під час виправлень (щоб головний агент вирішив, чи потрібна повторна перевірка).
- Результат final check: 404, нумерація, внутрішні посилання, пошук новин за 30 днів.
- Поточний статус документа й чи виконано критерій AGENTS.md, розділ 13.
- Інструменти: чи був доступний Chrome.
